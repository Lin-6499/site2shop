# 增量采集、源站缓存与快速预检

这些功能接入正式 `evidence-capture` 入口，默认启用，不依赖智能体记住额外步骤。完整采集计划仍是覆盖范围的唯一来源，不会因失败自动删去页面、视口或状态。

## 运行方式

```powershell
npm run site2shop -- evidence-capture --out <产物目录> --stage source
npm run site2shop -- evidence-capture --out <产物目录> --stage preflight
npm run site2shop -- evidence-capture --out <产物目录> --stage online
```

可选参数：

- `--precheck-only`：只运行预检，不保存正式状态截图，不执行整条状态链；`captureComplete` 必须为 false。
- `--refresh`：强制重新采集全部计划项，预检仍不能跳过。
- `--cache-max-age-hours 6`：缩短缓存有效期。默认 24 小时，允许 0–24；0 禁止复用。缓存命中不会延长原完成时间。

## 1. 增量与断点

以“页面路由 × 视口 × 完整状态流程”为可复用事务。每个状态和交互后原子写入检查点；流程全部完成才提交缓存。

中断后重新运行同一命令：完整且未变化的事务复用原证据；未完成/失败的事务从 initial 重建状态，按计划重放依赖步骤。不会从一张旧截图直接跳入后续表单状态，也不会重跑其他已经有效完成的事务。

目标缓存严格绑定阶段、计划、构建与草稿主题。新构建必须重新采集目标站，不把旧截图改写成新构建。旧 coverage 在替换前保存为内容寻址 artifact，当前 coverage 的 `priorCoverage` 可追溯。

## 2. 源站独立缓存

源站指纹包含源 URL、canonical、组件采集契约、源定位器、操作序列、视口、版本和采集器实现/依赖哈希，不包含目标定位器、目标构建与全局计划 revision。只改目标布局不会强制重抓未变化的源站流程。

每次复用前仍进行真实浏览器初始态检查，比较组件观测、页面文字、控件、图片、脚本/样式地址和内联样式。所有可达证据文件重新核对 SHA-256；损坏、缺失、过期、失败和部分记录均视为未命中。

跨计划 revision 复用会保存 `sourceProvenance`（原计划的哈希引用）。TypeScript 智能体复核门禁和 Python 契约门禁独立比较原/现源站契约，再校验原 artifact 的真实 revision，不改写时间戳和版本。当前覆盖清单仍必须绑定当前完整计划。

初始态指纹不能证明远端所有异步状态从未改变。因此保留 24 小时上限；已知源站部署、活动或动态应用变更时使用 `--refresh`，或更新计划 `sourceRevision`。后续双站交互复核、视觉判定、购买流程验收仍需执行，缓存不是自动通过凭证。

## 3. 采集前预检

顺序：静态契约/适配器/流程完整性 → 目标全部导航路由健康 → 各页面三端初始组件与第一个只读交互 → 正式全状态采集。

目标导航检查前移：404、密码页、挑战路由、canonical/最终路由错误或旧 build 会先失败，不再等商品全量截图之后才发现。页面检查确认三端组件定位器可用、首个操作和结果可观测；禁止业务写入。预检失败时本轮不进入正式状态截图采集，但旧完整事务缓存保留以便修复后续跑。

预检不是完整验收：它不穷举后续状态，也不自动产生智能体 pass。报告为 `<stage>-precheck.json`；进度与复用计数在 `<stage>-capture-result.json`。正式门禁仍检查当前完整清单、原始证据、布局契约、负向测试与智能体复核。

首次使用该版本没有可信缓存会正常完整采集。不会自动“收编”旧的无指纹报告；不承诺某个未经实测的整站加速百分比。
